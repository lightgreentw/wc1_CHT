# wc1_extract_text.py 操作說明

Wing Commander 1 中文化文字工具：**一支程式、四個指令**，涵蓋 WC1／Secret Missions 1（SM1）／SM2／SM1.5／Transfer。
只用 Python 3.8 以上的標準函式庫，不用安裝任何套件。

| 指令 | 用途 |
|---|---|
| `export` | 匯出遊戲用到的**全部英文文字**，並產生翻譯表樣板 |
| `check` | 檢核**既有翻譯表**與遊戲原文的差異 |
| `missed` | 查 DLL **未命中字串**（`wc1cht_missed.tsv`）在遊戲資料中的位置 |
| `sync` | 把已翻好的譯文自動帶入「同一句、寫法略有不同」的空白條目 |

---

## 1. 準備資料夾

把遊戲檔案放在一個資料夾，結構如下（檔名大小寫不拘）：

```
WC1資料夾\
 ├─ GAMEDAT\            BRIEFING.000/.001/.002/.015、MIDGAME.V00–V08、
 │                      COMMUNIC.DAT、COMMSM2.DAT、MODULE.000/.001/.002/.015 …
 ├─ Wing1_wcdx.exe      各版本的 exe（有的就掃，沒有就略過）
 ├─ SM1_wcdx.exe
 ├─ SM2_wcdx.exe
 └─ TRANSFER_wcdx.exe
```

- **資料片會覆蓋進同一個 GAMEDAT，這樣放就好**：版本由檔案副檔名（`.000`＝WC1、`.001`＝SM1、`.002`＝SM2、`.015`＝SM1.5）和 exe 的 PE 時間戳自動判斷，不靠檔名。
- 也可以直接指向 `GAMEDAT` 本身（exe 會到它的上一層找）。
- 路徑本身若不含 GAMEDAT，程式會**往下找兩層**，把每個找到的遊戲資料夾各算一組。
- **可以一次給多個資料夾**（例如兩份不同修補版的 gamedat）：文字會合併，同名但內容不同的檔案會在摘要列出，不同寫法各算一句並標出來源資料夾。

---

## 2. 快速開始

```
python wc1_extract_text.py export  D:\WC1  -o out  --table wc1zh.txt
python wc1_extract_text.py check   D:\WC1  --table wc1zh.txt  -o chk
python wc1_extract_text.py missed  D:\WC1  --missed wc1cht_missed.tsv  --table wc1zh.txt  -o ms
python wc1_extract_text.py sync    wc1zh.txt
```

- 指令名稱可省略，等於 `export`（相容舊用法）。
- 每個指令都有 `-h`：`python wc1_extract_text.py check -h`。
- 輸出資料夾不存在會自動建立；**同名檔案會被覆蓋**。
- 摘要會同時印在畫面上並存成 `*_summary.txt`。

## 3. `export`：匯出全部遊戲文字

```
python wc1_extract_text.py export <資料夾...> [-o 輸出資料夾] [--table wc1zh.txt] [--order normalized|source]
```

| 選項 | 說明 |
|---|---|
| `-o` | 輸出資料夾，預設 `wc1_text_export` |
| `--table` | 既有翻譯表。給了就會在樣板帶入已有譯文、標示尚未翻譯的句子 |
| `--order` | 樣板排序：`normalized`（預設）＝同一句的不同寫法排在一起；`source`＝依遊戲檔案出現順序 |

### 輸出檔

| 檔案 | 內容 |
|---|---|
| `wc1_all_text.tsv` | 每個**不同的字串**一列（寫法、空白、標點、用字只要有差就算不同句） |
| `wc1_all_text_occurrences.tsv` | **每一次出現**一列：版本、來源檔、位置、lipsync（口型）、anim（動畫指令） |
| `by_group\<群組>.tsv` | 依群組拆開的 `wc1_all_text.tsv` |
| `wc1zh_template.txt` | **翻譯表樣板**（`英文<TAB>譯文`，可直接翻譯後當 wc1zh.txt 用） |
| `wc1_untranslated.tsv` | 有 `--table` 才有：樣板中尚未翻譯的句子 |
| `wc1_skipped_nontext.tsv` | 只含格式碼或亂碼、不需翻譯的字串 |
| `export_summary.txt` | 統計、版本涵蓋數、資料夾差異、訊息 |

### 六個群組

| 群組 | 內容 |
|---|---|
| `dialogue` | 簡報、任務後對話、過場劇情（BRIEFING／MIDGAME）、降落台詞 |
| `combat_dialogue` | 空戰無線電對話（COMMUNIC.DAT／COMMSM2.DAT） |
| `combat_ui` | 空戰電腦與通訊選單 UI（exe） |
| `ui_label` | 星圖、酒吧、街機、階級、機型武器、勳章、任務／導航標籤（MODULE） |
| `story_text` | 開場、結局、製作名單字幕 |
| `system` | 系統、安裝、錯誤訊息 |

`wc1_all_text.tsv` 的欄位：`group`、`category`（細分類）、`text`（`\n` `\t` 已跳脫）、`in_table`（有 `--table` 才有）、`versions`、`sets`（多資料夾才有）、`n_occurrences`、`confidence`、`ws_flags`、`first_locations`。

- `confidence=low`：程式沒把握那是正式對話（例如口型字串殘留、很短的標籤），請目視確認。
- `ws_flags`：`dbl_space`（連續空格）、`lead_space`、`trail_space`、`space_at_LF`（換行旁有空格）。

### 樣板 `wc1zh_template.txt` 的格式

```
# ● [WC1] BRIEFING.000 res0 @0xB31
Goodbye, Spirit ... I hope I can fill the gap you leave.	再見了，「幽靈」…
# ● [SM1/SM2] BRIEFING.001 res0 @0xAA3
Goodbye, Spirit ... I will miss your soft-spoken advice.	再見了，幽靈…
# ▼ [SM15] BRIEFING.015 res0 @0xBDE
Goodbye, Spirit. I will miss your soft-spoken advice.	再見，幽靈。…
```

- `# ●`＝新的一句；`# ▼`＝與**上一句只差空白／標點／大小寫**的不同寫法（緊接在原句下方，方便對照與除錯）。用字不同的句子（例如 `Spirit ...` 與 `Spirit.`）會各自是 `●`。
- 註解行內 `[ ]` 是出現的版本，`{ }` 是只出現在部分資料夾時的資料夾名，後面是第一個出現位置。
- 譯文留空＝尚未翻譯（載入時會被略過，不影響遊戲）。
- 有 `--table` 時：key 完全相同就帶入譯文；只有近似寫法（唯一對應）時也會帶入，並在註解加上「〔譯文由近似寫法帶入，請確認〕」。
- 開頭有 `.` 的任務標籤（疑為旗標位元組）**同時列有點與無點兩種寫法**。

## 4. `check`：檢核翻譯表

```
python wc1_extract_text.py check <資料夾...> --table wc1zh.txt [-o 輸出資料夾]
```

用途：翻譯表和遊戲原文對不對得上。兩個方向都檢查。**兩個資料夾以上約需 1～2 分鐘**（有逐句相似度比對）。

### `check_1_table_keys_vs_source.tsv`：表內每一行 → 原文

| status | 意思 | 建議 |
|---|---|---|
| `MATCH` | key 與原文逐字相同 | 正常 |
| `MATCH_LENIENT_ONLY` | 只差結尾空白、空白、大小寫或標點才對上 | DLL 的寬鬆比對可能命中，要保險就補一行原文寫法 |
| `CHANGED` | 找到相近原文但用字不同 | 版本差異或舊表抄錯；依 `inline_diff` 決定新增一行或改 key |
| `KEY_SPLIT_AT_LF` | key 只是多行原文的其中一行（舊表在換行處切斷） | 改成完整多行句（`\n` 連起來） |
| `JUNK_KEY` | key 是口型字串，不是顯示文字 | 刪除 |
| `NO_SOURCE_FOUND` | 原文找不到 | 多半是詞彙表條目（人名、軍階）；其他請人工確認 |

`inline_diff` 的寫法：`[-只在表內-]{+只在原文+}`，空白以 `·` 顯示。

### `check_2_source_not_exactly_in_table.tsv`：原文每一句 → 表內

| status | 意思 | 建議 |
|---|---|---|
| `COVERED_LENIENT_ONLY` | 表內有只差寫法的句子 | 看 `diff_type` |
| `VARIANT_OF_KEY` | 與表內某句相近但**不同** | 新增一行並確認譯文 |
| `NOT_IN_TABLE` | 表內完全沒有 | 需要翻譯 |

`relevance` 欄：`ok`＝一般句子；`system`＝系統訊息；`nontext`＝只有格式碼／亂碼（不必翻）。

`diff_type`：`whitespace`（空白或換行）、`case`、`punctuation`、`var_spacing`（`$R$N` 與 `$R $N`）、`placeholder_notation`（`$S` 與 `%s`）、`spelling/minor_edit`（相似度≥0.85）、`reworded`（≥0.6）。

### `check_3_version_matrix.tsv`：版本矩陣

表內每個 key 在 WC1／SM1／SM2／SM15／TRF 各版本是 `OK`（逐字存在）、`VARIANT`（只有變體寫法，附內容與差異）或 `-`（該版本沒有）。**只列至少一個版本有變體的 key。**

> 判斷「哪些變體該新增一行」時：只差空白／標點／大小寫／方言省字，譯文可直接沿用；**人名、數字、單字不同**（例如 `Zeta`→`Mu` 小隊、`17:00`→`18:00`、`Mission`→`Wave`）必須另寫譯文，不能照抄。

## 5. `missed`：查未命中字串

DLL 在 ini 設 `[General] DumpMissed=1` 後會寫出 `wc1cht_missed.tsv`。這個指令把裡面的字串對回遊戲原文，告訴你它在哪、表內有沒有、該怎麼處理。

```
python wc1_extract_text.py missed <資料夾...> --missed wc1cht_missed.tsv [--table wc1zh.txt] [-o 輸出資料夾]
```

- **輸入格式很寬鬆**：任何 TSV 或純文字都可以；`#` 開頭、空行會略過；第一行若含 `text`／`string`／`key`／`count` 字樣視為標題列也會略過；`\n` `\t` 會還原。程式會**逐欄嘗試**，取第一個能對上遊戲原文的欄位，所以不必指定哪一欄是文字。
  （我手上沒有實際的 `wc1cht_missed.tsv` 範例，是依此寬鬆規則設計的；若欄位排列特殊對不上，請把前幾行給我調整。）
- 比對順序：逐字 → 寬鬆（空白／大小寫／標點）→ **模板**（原文含 `$T` `$D` 等變數，遊戲展開後的字串也能對回去）→ 相似度 ≥ 0.8。

### 輸出

| 檔案 | 內容 |
|---|---|
| `missed_lookup.tsv` | 逐筆結果：`status`、原文、版本、位置、`source_in_table`、`hint`（處理建議） |
| `missed_to_translate.txt` | 原文有、表內尚無的句子（**空譯文**，翻完貼進 wc1zh.txt） |
| `missed_summary.txt` | 各狀態筆數 |

### status 與建議

| status | 意思 | 建議 |
|---|---|---|
| `EXACT` | 原文有此句 | 表內沒有就加入；**表內已有卻仍未命中** → 檢查折行 `\n`、結尾空白、場景規則 `Skip` |
| `NORMALIZED:…` | 只差空白／標點／大小寫 | 用原文寫法當 key |
| `TEMPLATE` | 原文含 `$` 變數 | 表內 key 用**模板原文**（`$C` `$N` 由 DLL 還原，其餘由遊戲先展開） |
| `FUZZY` | 與原文某句相近但不同 | 版本差異或執行期改寫，需人工確認 |
| `NOT_FOUND` | 遊戲資料找不到 | 多半是執行期組合（數字、名稱）或 exe 的格式字串 |

## 6. `sync`：同步譯文

```
python wc1_extract_text.py sync wc1zh.txt [-o 輸出檔]
```

把**已有譯文**的條目，自動帶入**空譯文**、且「正規化後同一句」的條目。正規化只做：去開頭 `.`、空白收成一格、忽略大小寫。標點不同不會帶入。

- 同一句若有**多種不同譯文**，不帶入並列出，避免誤蓋。
- 預設輸出 `原檔名.synced.txt`，不會改原檔。
- 典型用途：任務標籤的有點／無點兩條，翻一條後同步另一條。

## 7. 翻譯表（wc1zh.txt）規則

| 項目 | 規則 |
|---|---|
| 格式 | UTF-8；每行 `英文<TAB>中文` |
| 跳脫 | `\n` 換行、`\t` Tab、`\\` 反斜線 |
| 註解 | 行首 `#`；空行略過 |
| 空譯文 | 略過（不影響遊戲） |
| 結尾空白 | key 與比對都忽略 |
| 大小寫 | DLL 有大小寫不分的備援；**只差大小寫的兩個 key，譯文必須相同**，否則互打架 |
| 重複 key | 後面的蓋過前面的 |
| 版本不同 | 寫法差一個字就是不同句，各自一行；變體放在原句下方 |
| `$` 變數 | `$C` `$N` 由 DLL 還原；`$T` 時間、`$D` 日期、`$R` 軍階、`$S` 系列資料、`$I` 數字等走模板比對 |

### `wc1zh_merged_v2.txt` 內的註解標記

| 標記 | 意思 |
|---|---|
| `# ▼ [AUTO]` | 版本變體，譯文照抄原句 |
| `# ▼ [COPY]` | 變體，人工確認可照抄 |
| `# ▼ [REVIEW]` | 變體，**譯文依差異改寫，請覆核** |
| `# ▼ [DOT]` / `[DOT-REVIEW]` | 開頭有 `.` 的任務標籤形式（`DOT-REVIEW`＝譯文由相近條目帶入，請確認） |
| `# ▼ [PLACEHOLDER]` | `$S` 換成 `%s` 等佔位符形式（**待確認 DLL 收到哪一種**） |
| `# ▽ [未翻譯]` | 尚未翻譯、譯文留空 |

## 8. 建議的工作流程

**A. 第一次整理／換新資料**
1. `export … --table wc1zh.txt` → 看 `export_summary.txt`。
2. 打開 `wc1_untranslated.tsv`，把句子翻到 `wc1zh_template.txt`（或直接翻 wc1zh.txt）。
3. `sync` 把有點／無點等姊妹條目補齊。

**B. 持續翻譯**
1. 一次翻一個群組（用 `by_group\*.tsv` 或樣板的群組區塊）。
2. 翻完 `check --table wc1zh.txt`：看 `NOT_IN_TABLE` 與 `VARIANT_OF_KEY` 是否還有漏。

**C. 實機除錯**
1. ini 開 `DumpMissed=1` 玩一輪，取得 `wc1cht_missed.tsv`。
2. `missed … --missed wc1cht_missed.tsv --table wc1zh.txt`。
3. 依 `hint` 處理；`missed_to_translate.txt` 的句子翻完貼進 wc1zh.txt。

**D. 取得新的遊戲資料或修補版**
把新資料夾與舊資料夾**一起**給 `export`／`check`，摘要會列出內容不同的檔案，只出現在其中一份的句子在樣板以 `{資料夾名}` 標示，各自補一行。

## 9. 已知限制

- **INTRO.DAT／INTRO1.DAT 未解碼**，開場字幕目前由 exe 內建字串涵蓋。
- **CAMP.000、CREDITS.TXT 未納入**。
- exe 字串區段以固定錨點字串界定；時間戳不在已知清單的 exe 依檔名猜版本，**找不到錨點的 exe 會略過**並在「訊息」提示（例如 DOS 版 `WC1.EXE`）。
- 版本已知時間戳：WC1 `0x32821571`、SM1 `0x3282101C`、SM2 `0x3294AA25`、Transfer `0x325D4FED`。
- MODULE 標籤開頭 `.` 為推論（疑似旗標位元組），所以兩種寫法都列。
- 程式是離線分析資料檔，**沒有進遊戲驗證**；`PLACEHOLDER`（`$S` 與 `%s`）以哪種為準需實機確認。

## 10. 疑難排解

| 狀況 | 處理 |
|---|---|
| 找不到 GAMEDAT | 確認路徑；或直接指向含 `BRIEFING.000` 的資料夾 |
| 摘要「訊息」說略過某 exe | 該 exe 不是 32 位元 PE 或找不到遊戲字串區段，通常是 DOS 版，可忽略 |
| 摘要說時間戳不在已知清單 | 版本依檔名猜，確認 exe 版本是否正確 |
| `check` 很慢 | 正常（逐句相似度比對）；只給一個資料夾會快一些 |
| 中文在 Windows 終端機顯示亂碼 | 程式已輸出 UTF-8；用 `chcp 65001`，或直接開輸出檔 |
| TSV 用 Excel 開亂碼 | 用「資料→從文字」並選 UTF-8，或改用文字編輯器 |
| 譯文沒有帶入 | `export --table` 比對 key 時忽略結尾空白，但空白數量、標點不同就是不同句 |
